# Static Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One private web app Wyatt opens instead of YouTube: a video picker that stays fresh, a live guide, a football Sunday board and a daily newspaper.

**Architecture:** Next.js app on Vercel. One client-rendered page (`app/page.tsx`) talks to one catch-all API route (`app/api/[...path]/route.ts`) that hands every request to a plain router in `lib/api.ts`. All logic lives in `lib/` as functions that take a `Db` and a `fetch`, so it is tested with vitest against a local Postgres and fake HTTP. Postgres through `DATABASE_URL` (Neon in production).

**Tech Stack:** Next.js 16, React 19, TypeScript, `pg`, `fflate` (unzip the Takeout export in the browser), `fast-xml-parser` (RSS), `lucide-react` (icons), vitest. Look: the shared `theme/` folder (copy of TallTeezSteez/theme, version 2026-11-15).

**Spec:** `docs/superpowers/specs/2026-11-15-static-design.md` (copy of Drive `2 Areas/Apps/Wyatt TV/Docs/Wyatt TV Replacement - Plan.md`).

## Global Constraints

- Free tiers only. No monthly fee anywhere.
- Just Wyatt. One password, set on first run. Every API call except setup/login/cron needs the session cookie.
- YouTube Data API: 10,000 units a day; at most 24 `search.list` calls a day. Never depend on YouTube RSS.
- No YouTube sign-in. Subscriptions and watch history come from a one-time Google Takeout import.
- No Shorts anywhere: videos under 180 seconds are never picked.
- A video marked seen is never picked again.
- Vercel Hobby: the scheduled job runs once a day (`0 11 * * *` UTC). Fresher data comes from refresh-on-open (uploads older than 3 hours, searches older than 20 hours).
- Theme rules (theme/README.md): no hand-written colors, corners or shadows; role variables only; one primary button per screen; settings follow theme/SETTINGS.md with Look first and About last.
- Secrets (YouTube key, Twitch id/secret) are stored in the database through Settings, never in the repo and never sent back to the browser.
- Any outside service failing (YouTube, Twitch, ESPN, a feed, weather) must not break the page it feeds: show what is known and say what is unavailable.
- Next.js 16: read `node_modules/next/dist/docs/` before using a Next API. `cacheComponents` is off; no middleware/proxy.

## Review Focus

1. Watch history exported as HTML instead of JSON (he skips the format step): import must still work. Test in Task 3.
2. YouTube quota runs out mid-gather: keep what was fetched, record the error, picks still serve from the catalog. Test in Task 5.
3. Pool runs low (he rerolls many times, or filters by a narrow shelf and time): return fewer picks with `exhausted: true`, never repeat a shown-this-session video and never error. Test in Task 6.
4. A video that cannot be embedded, or was removed: it still shows with an "Open on YouTube" button; player errors skip to the next pick. Test in Task 6 (flag carried through) and by hand in Task 12.
5. ESPN feed shape changes or is down on a Sunday: `/api/nfl` returns `{ok:false, games:[]}` and the board says scores are unavailable. Test in Task 9.

## Shared types (lib/types.ts)

```ts
export type Db = { query<T = any>(text: string, params?: unknown[]): Promise<{ rows: T[] }> };
export type Fetch = typeof fetch;
export type Topic = { id: string; name: string; keywords: string[]; queries: string[]; minMinutes: number; categoryIds?: string[] };
export type Video = { id: string; channelId: string; channelTitle: string; title: string; description: string; publishedAt: string;
  durationS: number; views: number; categoryId: string; tags: string; embeddable: boolean; liveState: 'none'|'live'|'upcoming';
  scheduledStart: string | null; thumb: string };
export type Pick = { id: string; title: string; channelId: string; channelTitle: string; durationS: number; publishedAt: string; views: number;
  thumb: string; embeddable: boolean; topics: string[]; isNew: boolean; reason: string; progressS: number; later: boolean };
export type TimeBucket = 'short' | 'hour' | 'long';   // 10-30 min, 30-80 min, 80+ min
```

### Task 5: Gather

**Files:** `lib/gather.ts`, `tests/gather.test.ts`

- `runGather(deps, opts: {force?: boolean; kinds?: ('uploads'|'search')[]}): Promise<{uploads?: {channels:number; videos:number}; search?: {queries:number; videos:number}; skipped: string[]; error?: string}>`.
- Uploads: up to 400 channels where `rating >= 0`, ordered by `subscribed desc, recent_count desc, watch_count desc`; 20 at a time; skip when the last uploads run is under 3 hours old unless `force`.
- Search: each topic's queries (at most 24 a day total, rotating by day of year), `publishedAfter` 21 days back, `videoDuration long` for topics with `minMinutes >= 20` else `medium`, order `viewCount`; skip when under 20 hours old unless `force`. Channels found by search are inserted with `source 'search'`.
- Videos upsert with `topics = classify(...)` plus the search topic. Videos under 180 s are stored with their duration (so they are filtered, not refetched).
- No YouTube key -> `{skipped:['no-key']}`.
- [ ] Tests: staleness skip; search call budget (never more than 24); **QuotaError after the first batch keeps that batch, sets `error`, writes `gather_log` with `ok=false`** (Review Focus 2); search topic is attached. Commit.

### Task 6: Scoring, picks, events

**Files:** `lib/score.ts`, `lib/picks.ts`, `lib/events.ts`, `tests/score.test.ts`, `tests/picks.test.ts`

- `scoreVideo(c: Candidate, now: Date): {score: number; reason: string}` — weights are the builder's: channel affinity (watch counts, rating), freshness (half-life 10 days), views per day for new channels, penalty per time shown without a click.
- `pickSet(cands: Scored[], {n, mixNew, rng}): Scored[]`: at most one per channel; `round(n*mixNew)` slots go to `isNew` candidates when available, the rest to known; weighted-random from the top of each group so rerolls differ.
- `getPicks(deps, {shelf?: string; time?: TimeBucket; n?: number; exclude?: string[]}): Promise<{picks: Pick[]; exhausted: boolean}>`. Candidate rules: `duration_s >= 180` (and `>= topic.minMinutes*60` on a shelf), not in `seen`, `vstate.vote` not -1, not skipped, channel rating not -1, `live_state = 'none'`, not in `exclude`, shown fewer than 4 times. Increments `vstate.shown`. Shelf ids: topic ids, plus `regulars` (known channels, any topic) and `later`.
- `GET /api/picks?shelf=&time=&n=&exclude=a,b`; `GET /api/home` -> `{tonight: Pick[], shelves: {id; name; picks: Pick[]}[], stale: boolean, counts}`.
- `applyEvent(deps, ev: {type:'up'|'down'|'skip'|'seen'|'progress'|'later'|'unlater'|'hide_channel'|'like_channel'|'unhide_channel'; videoId?: string; channelId?: string; seconds?: number})`; `POST /api/event`. `up` adds 1 to the channel rating; `down` marks skipped; `progress` at 80%+ of duration marks seen.
- `GET /api/library` -> `{later, continueWatching, recent, hiddenChannels}`.
- [ ] Tests: Shorts never picked; seen never picked; mix 0.5 with n=6 gives 3 new + 3 known when both exist; one per channel; exclude honored; **pool smaller than n returns what exists with `exhausted:true`** (Review Focus 3); non-embeddable video is returned with `embeddable:false` (Review Focus 4); `down` removes a video from later picks; hide channel removes all its videos. Commit.
